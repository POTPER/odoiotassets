# 12 烟雾传感器模块

标准教学入口为 [SmokeSensor_standard.py](SmokeSensor_standard.py)，原演示入口为 [SmokeSensor_Demo1.py](SmokeSensor_Demo1.py)。标准版使用模块 12 的 GPIO 5 数字输入，增加实验信息、参数检查、完整 CSV、同次源码归档及异常清理。

## 教学任务

模拟“设备间01”的烟雾状态监测。填写脚本顶部 `experiment_info` 中的考试编号、项目名称和项目位置，将项目名称设为“设备间烟雾状态监测”，把 `SLEEP_TIME` 从初始 1 秒改为题面要求的 0.5 秒。观察正常、触发和恢复过程，每种状态至少保留 3 条有效采样，按 Ctrl+C 结束。

`SLEEP_TIME` 是每次读取、记录及通信完成后的等待时间，须为有限正数。相邻采样实际间隔还包含处理耗时，可用 CSV 的“实验累计毫秒”核对。程序持续采集，不按次数自动结束。

## 板端运行

使用 Python 3.8 或以上版本，在 RK3588 Linux ARM64 实训箱的本模块目录执行：

```bash
python3 SmokeSensor_standard.py --check
python3 SmokeSensor_standard.py
python3 SmokeSensor_standard.py --module 12 --output-dir ./成果输出
```

需要同目录的 `libSmartSensorDriver.so`。标准版通过脚本所在目录的绝对路径加载驱动，不依赖原演示的 Python 包。`--help` 与 `--check` 均不加载驱动；`--check` 只验证采集间隔、模块编号及驱动文件存在性，不验证驱动架构、硬件或通信。一次运行一个占用该模块的程序。

## 状态与兼容性

GPIO 初始化沿用原演示的 `GpioInInit(模块编号, 5, 0, 1, 0)`。采用原演示循环的低电平触发约定：

| 原始电平 | CSV 烟雾状态 | JSON `Answer.SmokeSensor_Status` |
| --- | --- | --- |
| 1 | 正常 | 字符串 `"0"` |
| 0 | 触发 | 字符串 `"1"` |
| 负数或其他非法值 | 未知，读取失败后停止 | `"未知"` |

首次和后续采样使用同一转换规则。原演示首次直接上报原始电平，后续则反相；其失败分支还误用了 `Grating_Status`。标准版统一使用 `SmokeSensor_Status`，初始化返回负值也会停止。初始化、退出及清理事件上报“未知”，不沿用上一次有效读数；其通信和输出状态均为 0，连接状态只表示软件连接过程。

这里只采集数字触发信号。目录中的 [SmokeSensor.py](SmokeSensor.py) 另有 ADS1115 电压映射逻辑，标准版不使用该浓度估算。实际触发极性、正常和触发现象需板端核对。

## 成果与验收

- 默认保存到当前用户桌面 `成果输出/考试编号/项目名称/`；`--output-dir` 替换成果根目录。同次 CSV 与入口源码同名，重名自动递增。复现归档源码仍需驱动库和实训箱。
- CSV 每行表示一次采样、生命周期或异常事件，包含实验信息和“记录时间、实验累计毫秒、模块编号、采样序号、动作、采集间隔(秒/次)、原始电平、烟雾状态、执行结果、错误信息”。采样序号从 1 开始；生命周期事件使用 0。失败和非采样行的原始电平留空，不代表电平 0。
- 核对正常、触发及恢复的有效采样，结合现场观察确认变化；读取失败行的结果为“读取失败”，原因写入“错误信息”。JSON 保存或 UDP 发送失败另记一行，保留原有效采样。
- `student_data/student_data.json` 滚动保留最近最多 5 条事件，沿用 `Name=SmokeSensor` 等原厂字段，按 16 字节小端包头、每包最多 1000 字节数据发送到 UDP `127.0.0.1:8088`。JSON 不是完整采样历史，UDP 发送成功也不证明接收端已收到。
- Ctrl+C、SIGTERM 和运行异常进入清理流程，分别尝试断开模块、注销驱动及关闭 UDP。清理某项失败后继续尝试后续项。板端需在退出后再次运行，确认模块可重连。

提交同次 CSV、自动归档源码及现场观察记录。本次通过 Python 3.8 语法兼容检查、命令行检查和模拟驱动验证，覆盖正常/触发转换、非法读数、初始化与清理失败、CSV/源码归档及 JSON/UDP 格式；板端读数、极性、实际间隔和重连尚未实测。
