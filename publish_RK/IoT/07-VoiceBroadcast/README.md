# 07 语音播报模块

标准教学入口为 [VoiceBroadcast_standard.py](VoiceBroadcast_standard.py)，原厂示例为 [VoiceBroadcast_Demo1.py](VoiceBroadcast_Demo1.py) 和 [VoiceBroadcast_Demo2.py](VoiceBroadcast_Demo2.py)。标准版沿用原厂串口与 GBK 文本发送方式，增加教学任务、实验信息、循环播报、音量设置、参数检查、CSV 记录、源码归档和异常退出清理。

## 教学任务

模拟施工现场语音安全提示：播报“设备已就绪，请注意施工安全”，音量 3 级，发送成功后等待 8 秒再发送。任务名称为“现场语音播报调试”，任务位置为“设备管理区01”。连续观察至少 3 个完整轮次，核对播报内容、音量和节奏，按 Ctrl+C 结束。

填写入口顶部的 `experiment_info`，按题面修改 `TEXT`、`VOLUME` 和 `BROADCAST_INTERVAL`。初始文本为“欢迎使用品茗物联网实训台”，初始音量为 4，初始间隔为 5 秒，需由学生调整。音量必须为 1～4 的整数，间隔必须为有限正数；文本必须非空、可编码为 GBK，不可包含控制字符或协议命令尖括号。较长文本应相应增加间隔，避免连续发送造成截断或排队，具体表现需现场观察。

## 板端运行

在 RK3588 Linux 实训箱的本模块目录执行：

```bash
python3 VoiceBroadcast_standard.py
python3 VoiceBroadcast_standard.py --module 7 --output-dir ./成果输出
```

需要 Python 3、本目录的 `libSmartSensorDriver.so` 和可连接的语音播报模块。标准版直接调用原厂动态库，仅使用 Python 标准库，不依赖本目录的包装模块；`--help` 不加载硬件驱动。动态库和状态文件按入口所在目录定位。

默认模块编号为 7，串口通道为 2，TX 为 22，RX 为 23，串口参数沿用原厂的 `9600, 0, 8, 1`。初始化后通过原厂 ASCII 发送接口发送 `<V>音量等级`，等待 0.3 秒，再循环发送 GBK 文本；长度使用编码后的字节数。音量命令来自原示例的注释方案，标准版实际启用，其生效情况和等待时间须板端确认。

每轮包含一次文本发送及等待。间隔从发送调用成功返回开始计时，文件写入、通信及下一次发送可能增加实际间隔。程序没有接收播报完成反馈，“本轮完成”仅表示本轮发送与等待均已完成。

## 成果与验收

- 默认保存至当前用户桌面下 `成果输出/姓名或小组/任务项目/`；`--output-dir` 替换成果根目录。同次 CSV 与入口源码同名，重名时递增编号。
- CSV 每行表示一次指令、轮次完成、生命周期或异常事件，包含实验信息及 `记录时间`、`实验累计毫秒`、`模块编号`、`轮号`、`动作`、`播报间隔(秒)`、`音量`、`播报文本`、`执行结果`、`错误信息`。轮号 0 为初始化和退出等事件。
- `驱动指令成功` 表示相关驱动调用通过返回值检查；扫描、串口初始化、发送、注销与断开以负值为失败，连接模块要求返回正值，在线检查要求返回 1。驱动库初始化及注销无返回值检查。发送未返回负值不能证明硬件已接收完整文本或扬声器已经发声。
- 现场检查至少 3 轮的实际播报内容、清晰度、音量与节奏，结合 CSV 中“发送播报文本”和“本轮完成”记录验收。CSV 音量列记录配置值，实际效果须现场核对。
- `student_data/student_data.json` 保留最近最多 5 条状态，沿用 `Name=VoiceBroadcast`、`Answer.Voice_Status`、`Answer.Action`、`Target_Value`、`Output_Frequency` 和三个状态字段。`Voice_Status` 使用“未知”“串口就绪”“已发送”“串口关闭”描述程序状态，不能据此判断正在发声。
- 状态按原厂 16 字节小端分包头及每包最多 1000 字节载荷发送至 UDP `127.0.0.1:8088`。分包头依次为组号、总包数、包序号（从 0 开始）、本包载荷字节数，各占 4 字节。发送成功不代表接收端已收到；JSON 为状态窗口，完整实验记录以 CSV 为准。
- 连接状态表示程序保存的连接状态，通信和输出状态表示当前事件是否为驱动指令成功；轮次完成、用户停止等非驱动事件为 0。这些字段不能证明实时在线或实际播报效果。
- Ctrl+C、SIGTERM 和运行异常进入清理流程，依次尝试注销串口、断开实际使用的模块、注销驱动和关闭 UDP。单项失败仍继续清理并记录。退出时没有发送硬件停止播放命令，已发送的语音可能继续播放；断电和强制杀进程无法执行 Python 清理。

原示例只发送一次文本、音量设置代码被注释，且退出时断开模块编号写为 5；标准版采用循环发送、实际发送音量命令并按当前模块编号断开，检查发送返回值。原示例和驱动文件保留。

提交同次 CSV、自动归档源码与现场观察记录。源码归档仅为入口快照，复现仍需要动态库与板端环境。
