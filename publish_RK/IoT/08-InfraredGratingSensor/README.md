# 08 红外光栅传感器

标准教学入口为 [InfraredGratingSensor_standard.py](InfraredGratingSensor_standard.py)，原厂示例为 [InfraredGratingSensor_Demo1.py](InfraredGratingSensor_Demo1.py)。标准版保留 GPIO 电平采集及 JSON/UDP 协议，增加教学任务、实验信息、参数检查、完整 CSV、同次入口源码归档和退出清理。

## 教学任务

模拟施工通道遮挡检测调试。填写入口顶部的 `experiment_info`，任务项目改为“通道光栅状态采集”，任务位置改为“施工通道01”，将 `SLEEP_TIME` 从初始的 0.1 秒改为题面要求的 0.2 秒。

依次保持无遮挡、遮挡、恢复无遮挡各至少 3 秒，重复 3 轮后按 Ctrl+C 结束。结合现场观察与 CSV，说明电平 0、1 各对应哪种状态。原示例未明确遮挡极性，标准版只记录原始电平，不预设对应关系；也不将每个高电平样本计为一次通行。

## 板端运行

在 RK3588 Linux 实训箱的本模块目录执行：

```bash
python3 InfraredGratingSensor_standard.py --help
python3 InfraredGratingSensor_standard.py
python3 InfraredGratingSensor_standard.py --module 8 --output-dir ./成果输出
```

使用 Python 3.8 或以上版本，需同目录的 `libSmartSensorDriver.so` 和可连接的模块。标准版直接调用动态库，不依赖原厂的三个 Python 包装文件；驱动按入口所在目录定位，`--help` 不加载驱动或连接硬件。

默认模块编号 8、GPIO 引脚 5；沿用原厂 `GpioInInit(8, 5, 0, 1, 0)` 的下拉输入配置。启动后扫描并等待 2 秒，检查模块在线、连接和初始化结果，再立即进行首次采样。后续间隔从上次读取返回时开始计时，文件写入和上报耗时计入等待；实际间隔还受系统调度与驱动耗时影响。

`SLEEP_TIME` 必须为有限正数。每次读取仅接受 0 或 1，负数及其他值均记为失败并停止，不转换为正常电平。标准版检查初始化返回值；原 Demo 只检查初始化是否抛出异常，并将循环内除 1 外的非负值转换为 0，首次读数则直接输出，两者在错误处理与类型一致性上存在区别。

## 成果与验收

- 默认归档到运行用户桌面下的 `成果输出/姓名或小组/任务项目/`。`--output-dir` 替换成果根目录，同次 CSV 与源码同名，重名递增编号。源码是实际运行入口的快照，复现仍需原厂动态库。
- CSV 列为 `记录时间`、实验信息中的自定义字段、`实验累计毫秒`、`模块编号`、`序号`、`动作`、`原始电平`、`采集间隔(秒)`、`执行结果`、`错误信息`。每次采样尝试一行，序号从 1 递增；初始化、退出及辅助事件通常为序号 0，JSON/UDP 故障事件沿用对应采样序号。非有效采样行的电平留空，错误写入错误信息列。
- 核对参数、3 轮现场操作与采样电平变化，用采样行的累计毫秒核对实际间隔。`采集成功` 仅说明驱动返回有效电平，不能单凭固定 0 或 1 判断光栅接线与遮挡检测均正常。CSV 不自动标记现场操作轮次，应另附观察记录；本程序无去抖、通行计数或报警功能。
- `student_data/student_data.json` 保留最近最多 5 条状态，沿用 `Name=InfraredGratingSensor`、`Answer.Grating_Status`、`Target_Value.Grating_Status="0"`、`Output_Frequency` 和三个状态字段。成功读数统一为字符串 `"0"` 或 `"1"`，其余事件为 `"未知"`。目标值 0 是兼容原协议的字段，不代表已确认的无遮挡电平或合格判据。
- 状态通过 UDP `127.0.0.1:8088` 发送，沿用四个 4 字节小端无符号整数组成的 16 字节包头（组号、包数、包索引、载荷长度），每包最多 1000 字节载荷。发送成功不证明接收端收到。JSON 为滚动状态窗口，完整历史以 CSV 为准。
- 连接状态表示程序保存的连接状态；通信和输出状态仅在有效采样事件时为 1。初始化、结束等事件的通信和输出状态为 0，不能据此断定硬件离线。CSV 先于 JSON/UDP 写入，后两者失败会另记事件并继续采样；采样行的 CSV 写入失败则停止采集。
- Ctrl+C、SIGTERM、读数异常或启动失败均进入清理流程，按已尝试的步骤断开模块、注销驱动并关闭 UDP。单项清理失败仍继续后续清理。断电与强制杀进程无法执行 Python 清理。

提交同次 CSV、自动归档源码和现场观察记录。已通过语法、命令行帮助及替身驱动检查；板端实际电平、遮挡极性、采样节奏和退出重连仍需实机验收。
