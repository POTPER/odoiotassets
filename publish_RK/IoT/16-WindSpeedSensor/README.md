# 风速传感器标准实训

标准入口为 [WindSpeedSensor_standard.py](WindSpeedSensor_standard.py)，原厂入口 [WindSpeedSensor_Demo1.py](WindSpeedSensor_Demo1.py) 保留。标准入口增加实验信息、配置检查、完整 CSV、同次源码归档及退出清理，沿用原厂 JSON/UDP 字段。

## 开始实验

在 RK3588 Linux 板端的本模块目录运行，需要 Python 3、本目录配套 Python 文件和 `libSmartSensorDriver.so`。

```bash
python3 WindSpeedSensor_standard.py --help
python3 WindSpeedSensor_standard.py --check
python3 WindSpeedSensor_standard.py
# 可指定成果根目录
python3 WindSpeedSensor_standard.py --output-root ./成果输出
```

先填写入口顶部 `experiment_info`，再按教学任务将 `SLEEP_TIME` 从默认1秒改为2秒。改变风杯转速，至少记录10次有效采样，包含静止和转动两种状态，按 Ctrl+C 结束。间隔是一次采集、记录及上报后的等待时间，实际采样周期还包含这些操作的耗时。

`WIND_SPEED_TARGET_VALUE`、`WIND_SPEED_MAXIMUM_VALUE` 默认0，仅记录和上报，不触发报警；0表示未设置。可填写0～65535范围内的原始数值，该范围来自16位寄存器表示范围，不代表传感器物理量程。

## 硬件与数值约定

模块地址沿用原厂入口的 **15**，串口通道2，TX/RX为23/22，串口配置为9600、8N1。目录编号16与模块地址含义不同，现场核对地址和接线后调整系统配置。

问询指令沿用 `01 03 00 00 00 02 C4 0B`，按原厂代码从9字节回包的索引3、4提取大端无符号整数：`(frame[3] << 8) | frame[4]`。未自行换算为 m/s；原厂代码未注明单位、倍率及完整帧协议，需对照设备手册和实测确认。0是有效原始值，不能据此判断设备掉线。

等待扫描2秒并检查在线、连接后初始化串口。每次读取最多尝试3次；返回0时重试，连续无响应、负返回值、长度不等于9或超过缓冲区时停止并记录失败。`READ_TIMEOUT` 沿用原厂整数1，其时间单位以及驱动返回值是否为字节数需板端核对。当前未校验帧头、字节数字段或CRC，不据此认定数据精度。

## 数据与成果

CSV默认保存在当前运行用户桌面的 `成果输出/考试编号/项目名称/`，文件名包含微秒时间戳，同名 `.py` 为本次运行入口源码。`--output-root` 替换“桌面/成果输出”根目录。提交同次 CSV、源码及现场观察记录，配套驱动仍使用本模块目录文件。

CSV包含实验信息及 `记录时间、采样序号、模块编号、风速原始值、风速目标原始值、风速最大原始值、采集间隔(秒)、记录类型、结果、错误信息`。每次有效采样一行；初始化、停止、运行异常、上报失败和清理失败另记事件行，事件行的测量字段为空。采样序号表示尝试次数。文本字段以公式字符开头时加单引号，便于表格软件安全查看。

`student_data/student_data.json` 仅保留最近5条，UDP通过原厂 `UdpPackage` 向 `127.0.0.1:8088` 分包发送同一历史列表。`Name` 为 `WindSpeedSensor`，`Answer`、`Target_Value`、`Maximum_Value` 的子字段均为 `WindSpeed`；`Exceeding_Limit_Times` 沿用3，为协议字段，不表示程序实现了超限统计。正常采样三个状态均为1；停止或失败时发送零值及状态0，应结合状态解释。UDP发送成功不证明接收端已收到，JSON也不替代完整CSV。

## 验证与验收

退出时依次尝试释放串口、断开模块、注销驱动库和关闭UDP，单项失败仍继续其余步骤。运行、上报或清理失败返回非零退出码。归档文件创建失败时程序报错退出。

验收时核对实验信息、2秒等待设置、至少10行成功采样、静止与转动的现场观察、JSON字段和接收端显示；结束后核对停止记录及离线状态。`--check` 仅检查配置、配套文件存在及 Python 语法，不加载动态库。串口通信、响应格式、地址、单位、倍率和测量精度仍需板端实测。
