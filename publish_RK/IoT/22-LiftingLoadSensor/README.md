# 22 吊重传感器标准实训

标准入口为 [LiftingLoadSensor_standard.py](LiftingLoadSensor_standard.py)，原厂入口 [LiftingLoadSensor_Demo1.py](LiftingLoadSensor_Demo1.py) 保留。标准版提供实验参数、配置检查、RS232吊重读取、启动去皮确认、完整CSV、同次源码归档及退出清理。

## 开始实验

填写入口顶部 `experiment_info`，按任务将 `SLEEP_TIME` 从1秒改为2秒，并设置 `TARGET_VALUE` 和 `MAXIMUM_VALUE`（克）。目标值只记录和上报；最大值为0表示未设置，非零时统计有效吊重严格大于最大值的采样次数，等于不计数。持续超限逐次累计，不触发执行器。

在RK3588 Linux板端进入本目录运行，需要Python 3、同目录 `UdpPackage.py` 和 `libSmartSensorDriver.so`，无第三方Python包依赖。标准入口自行声明驱动接口，不导入会立即加载动态库的原厂 `SensorModule.py`、`RS232Module.py` 或 `LiftingLoadSensor.py`。

```bash
python3 LiftingLoadSensor_standard.py --help
python3 LiftingLoadSensor_standard.py --check
python3 LiftingLoadSensor_standard.py
python3 LiftingLoadSensor_standard.py --output-root ./成果输出
```

`--help` 和 `--check` 不加载动态库；后者检查参数、配套文件存在以及入口和UDP封装语法，不验证驱动ABI或硬件。驱动通过脚本目录绝对路径加载，运行时无需依赖当前工作目录。

默认模块地址 `MODULE_INDEX=15`，沿用原厂设置，与目录序号22不同，须现场核对。串口通道2，TX=23、RX=22，9600波特率，参数为9600/0/8/1；扫描等待2秒后检查在线并连接。`READ_TIMEOUT=1` 沿用原厂整数参数，其单位与驱动返回值语义须板端确认。

启动前卸载并保持静止。默认 `TARE_ON_START=True`，每次启动发送一次去皮命令并核对完整8字节回显；无应答或回显错误即记录失败并退出，不自动重复发送去皮。回包丢失时设备可能已去皮，不能将超时等同于设备未执行。应答确认只证明响应符合约定，零点效果需现场观察。需保留当前零点时可在源码将该参数改为 `False`，CSV记录“未执行”。

去皮后逐步挂载、卸载并保持静止，至少观察10次有效采样，按Ctrl+C结束。实际采样周期包含通信、记录、上报及末尾的 `SLEEP_TIME`，长于设置的等待时间。

## 读数与异常边界

读取命令为 `01 03 00 00 00 01 84 0A`，去皮命令为 `01 06 00 11 00 01 18 0F`。标准版按这两条命令所呈现的Modbus RTU格式校验：读取响应须为7字节、帧头为 `01 03 02`，并通过CRC16校验；第3、4字节（从0计数）合成大端无符号整数。去皮须完整回显原命令。协议格式与驱动是否返回实际字节数仍须板端核对。

沿用原厂 `吊重(g)=原始值/10`，保留两位小数，例如1234对应123.4 g；并未确认量程、精度或负数编码。16位无符号值不可能达到原厂判断中的65536，标准版不保留该分支。合法的零读数可作为有效采样；连续3次读取无响应则记录异常并退出，不以0冒充测量值。负驱动返回值、短帧、帧头或CRC错误同样记录并退出；只有返回0时重试读取，读取不重复去皮。

吊重大于 `SHAKE_THRESHOLD=6000` g时沿用原厂异常提示“请保持吊重静止”，CSV仍保留原始值和换算值，标记“异常读数”，不累计超限次数；等于6000 g属于有效读数。此阈值不能证明异常由晃动造成，也不是已确认的额定量程。

## 成果与验收

默认成果位于当前运行用户桌面 `成果输出/考试编号/项目名称/`；`--output-root` 替换成果根目录。每次生成含微秒时间戳的同名 `.csv` 和 `.py`，分别为完整记录与入口源码快照，复现仍需本目录UDP封装和驱动库。

CSV每次采样一行，包含实验信息，以及 `记录时间、采样序号、模块编号、吊重原始值、吊重(g)、读数状态、吊重目标值(g)、吊重最大值(g)、超限累计次数、采集间隔(秒)、记录类型、结果、错误信息`。初始化、去皮、停止、运行异常、上报或清理失败、结束另记事件行；事件行测量字段为空。序号表示采样尝试次数。文本以公式字符开头时添加单引号，便于表格软件查看。

`student_data/student_data.json` 保留最近最多5条，沿用原厂 `Name=LiftingLoadSensor` 及 `Answer/Target_Value/Maximum_Value` 中的 `LiftingLoadSensor`，保留 `Output_Frequency、Exceeding_Limit_Times、Status`。超限次数由原厂固定3改为本次有效采样的累计次数。正常采样三个状态均为1；异常读数时均为0，值为提示字符串；退出或失败时均为0，值为0，不能解释为测得0 g，也不能仅据状态推断物理连线。

UDP沿用四个小端32位无符号整数包头，每包最多1000字节数据，发送至 `127.0.0.1:8088`；发送成功不证明接收端收到。JSON供显示使用，不替代完整CSV。

Ctrl+C、SIGTERM和运行异常触发释放串口、断开模块、注销驱动库、关闭UDP，各项独立尝试。运行、上报或清理失败返回非零退出码。强制终止或断电不能保证清理。在线要求返回1、连接要求正值，其他有返回码的初始化或清理操作以负值为失败，这些约定沿用现有接口并待实测确认。

提交同次CSV、源码快照及现场观察记录，核对至少10次有效采样、空载零点、挂载卸载趋势、超限边界和接收端显示。已完成静态检查、帮助检查及模拟驱动验证，覆盖换算、CRC与错误帧、超时重试、单次去皮、CSV和源码归档、超限计数、JSON/UDP封装、正常中断与失败清理；未进行板端实测。
