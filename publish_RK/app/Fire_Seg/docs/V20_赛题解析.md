# V20 赛题解析（教师参考）

本解析对应本目录的 `fire_yolo26_v20.py` 学生版和 `fire_yolo26_v20_answer.py` 答案版。两版共用识别、显示、声音与记录模块。学生版保留可运行但不完整的示例，答案版提供正确配色和联动条件。

## 一、从工程背景提取要求

“分区动火预警调试”是本次任务名称，“施工现场监控点01”是覆盖三个区域的监测点位。监测点位不是某一个区域，CSV 中的“施工区域”另行记录实际测试区域。

| 题目信息 | 程序需要实现的行为 |
|---|---|
| 钢筋加工区、临时作业区、材料堆放区分别在画面左、中、右 | 系统按画面宽度三等分，以火焰检测框中心确定所属区域 |
| 钢筋加工区办理了动火审批 | 该区授权有效期间有火焰时保持静音 |
| 钢筋加工区授权失效后仍有火焰 | 请求“提示音1” |
| 临时作业区未安排动火 | 该区有火焰时请求“提示音2” |
| 材料堆放区存放可燃物、禁止动火 | 该区有火焰时请求“警报音”，钢筋区授权不能免除它的报警 |
| 三区分别使用绿色、纯黄色、纯红色 | 修改区域范围框及底部名称背景的 BGR 配色 |
| 每种成果分别验证并提交 | 完成四项摄像头展示，提交本次入口源码和四行 CSV |

本题考查从题面提取配置、比较数量、组合布尔条件和调用接口。模型训练、NPU 驱动、线程、区域中心计算和 CSV 写入已经由系统完成，学生无需重写。

## 三、TODO 1：区域配色为什么这样写

OpenCV 颜色按 **BGR：蓝、绿、红** 排列，每个分量取 0～255 的整数。

```python
COLOR_REBAR_AREA = (0, 255, 0)            # 左侧钢筋加工区：纯绿色
COLOR_TEMPORARY_WORK_AREA = (0, 255, 255) # 中间临时作业区：纯黄色
COLOR_MATERIAL_AREA = (0, 0, 255)         # 右侧材料堆放区：纯红色
```

绿色只打开绿色分量；黄色由绿色和红色组成；红色只打开红色分量。若误按 RGB 顺序填红色 `(255, 0, 0)`，画面会显示蓝色。

学生版的初始配色是蓝色，需要按题面修改。系统将同一颜色同时用于区域范围框和底部名称背景，名称使用 `Arial-Unicode.ttf`，文字自动选择深浅。

这里调整的是三个固定区域的配色。随火焰移动的检测框由置信度控制：高分实测框为红色，低分实测续跟框为黄色。它们与区域配色是两项不同设置。钢筋区范围框保持绿色，也不代表授权永远有效，应查看授权状态和倒计时。

## 四、TODO 2：可以直接使用哪些变量和接口

系统在每帧推理成功后调用 `control_buzzer(...)`，自动提供四个参数：

| 参数 | 含义 |
|---|---|
| `material_fire_count` | 本帧材料堆放区的高置信度火焰数量 |
| `rebar_fire_count` | 本帧钢筋加工区的高置信度火焰数量 |
| `temporary_work_fire_count` | 本帧临时作业区的高置信度火焰数量 |
| `permit_valid` | 钢筋区本次授权是否仍有效，`True` 有效，`False` 已到期 |

数量均为整数，`> 0` 表示至少识别到一个火焰。低置信度火焰和烟雾不计入这些数量。当前帧漏检时不补历史框，也不能用历史检测结果维持报警条件。

声音接口由系统提供：

| 接口 | 请求的声音 |
|---|---|
| `buzzer.alarm()` | 警报音：一组三声 |
| `buzzer.notice()` | 提示音1：一组一声 |
| `buzzer.notice2()` | 提示音2：一组两声 |
| `buzzer.reset()` | 静音，停止后续循环；正在执行的一组按原流程结束 |

学生只需编写条件判断。每次函数调用必须执行一次声音接口，不需要写等待、循环、线程或驱动操作。

## 五、正确条件与解释

```python
def control_buzzer(material_fire_count, rebar_fire_count,
                   temporary_work_fire_count, permit_valid):
    if material_fire_count > 0:
        buzzer.alarm()
    elif rebar_fire_count > 0 and not permit_valid:
        buzzer.notice()
    elif temporary_work_fire_count > 0:
        buzzer.notice2()
    else:
        buzzer.reset()
```

1. **材料区用 `> 0`。** 题目说“一旦出现火焰”，一个火焰也必须报警。学生初始示例的 `> 1` 会漏掉单个火焰，而且 `notice()` 的声音类型也不符合材料区要求，两处都要调整。
2. **钢筋区用 `and not permit_valid`。** 必须同时满足“钢筋区有火”和“授权已到期”。只有授权到期而没有火，不能请求提示音；有火但仍获授权，也应静音。`not` 用于取反布尔状态。
3. **临时作业区不使用钢筋区的授权。** 该区未安排动火，只要有火就提示，不能让其他区域的授权覆盖它。
4. **`else` 保证明确提交静音请求。** 无火，或只有授权有效期内的钢筋区火焰时，均进入静音分支，停止后续鸣叫循环。

`if / elif / else` 保证一次只调用一个接口。本题按一次展示一个区域进行验收，不额外设置多区域同时报警的考点。现有代码在多区同时有火时只执行第一个满足条件的分支，不会同时播放三种声音；这种画面也不会填入四项单区成果记录。

不要只在初始示例后追加代码而保留错误的条件和接口；应整体核对或替换 TODO 2 中的判断。若使用多个独立 `if`，可能同一帧调用多次接口，或后续 `reset()` 覆盖前面的请求。系统会将无调用、多调用或判断函数异常记入异常记录，并停用蜂鸣器。

## 六、授权倒计时如何工作

实际授权固定属于钢筋加工区，由系统提供 `permit_valid`，没有需要学生填写的 `AUTHORIZED_REGION` 文字变量。

- `PERMIT_DURATION` 位于系统配置区，当前默认 **60 秒**。题面没有限定具体秒数，可为了完成测试改为有限正数，保存并重启后生效。
- 在**首帧推理成功后**开始倒计时，首帧没有火焰也会计时。不是等钢筋区首次有火才开始。
- 授权有效时 `permit_valid=True`；倒计时结束变为 `False`，之后持续未授权，不自动续期。
- 重新启动程序会开始一次新的实验和授权计时，不能把两次运行的 CSV 当成同一次四项测试。

建议先完成钢筋区授权有效期间的展示，再完成其他区域，最后等待到期验证钢筋区提示音1。若授权时间不够，可以调整时长后重启并重新完成本次四项记录。

## 七、四项现场验证与 CSV

每次只在一个区域展示火焰卡片，让高置信度识别及声音请求保持稳定至少默认 **0.3 秒**。卡片跨界时按火焰框中心归属区域，尽量将火焰图案完整放在区域内部。

下表是答案版完成全部展示后的预期六项观察字段；实际 CSV 还会在前面添加考试编号、项目名称、监测点位。

| 施工区域 | 区域颜色（BGR） | 是否识别到火焰 | 授权状态 | 是否警报 | 警报类型 |
|---|---|---|---|---|---|
| 材料区 | (0, 0, 255) | 是 | 不适用 | 是 | 警报音 |
| 钢筋区 | (0, 255, 0) | 是 | 有效 | 否 | 静音 |
| 钢筋区 | (0, 255, 0) | 是 | 已到期 | 是 | 提示音1 |
| 临时作业区 | (0, 255, 255) | 是 | 未授权 | 是 | 提示音2 |

CSV 固定 **四行、九列**，不输出火焰数量、自动得分或系统参考答案。颜色取本次实际配置，声音取学生函数实际提交的请求；学生逻辑错误时也如实记录。例如单个材料区火焰在初始示例中会记录为“识别到火焰：是、是否警报：否、警报类型：静音”。教师再按题面核对。

尚未完成的项目保留“未验证”。无高分火焰、仅低分、多区同时出现或识别异常都不能完成单区成果。由于无检测结果时无法知道卡片位于哪一区，不会自动给某一区填写“未识别”。同一项重复展示保留最近一次稳定观察，钢筋区的两个授权时段分别保存。

“是否警报”记录的是**软件请求**，不能证明蜂鸣器已经实际发声。须现场听音确认硬件联动，并观察范围框和名称背景的颜色。另做撤去卡片、仅低分及烟雾不报警检查，但不增加主表行数。

## 八、运行与提交

学生运行 `python3 fire_yolo26_v20.py`；教师可运行 `python3 fire_yolo26_v20_answer.py` 对照。一次只运行一个入口。RK3588 沿用包内 RKNN 模型及 RKNNLite NPU 环境，无需安装 Ultralytics，也无需重新训练。

正常退出后，当前用户桌面的 `成果输出/考试编号/项目名称/` 中保存：

- 本次四行 CSV。
- 本次实际运行入口的 `.py` 源码副本，文件名与 CSV 同次对应。
- 若有异常，另附同次 `_异常.csv`。

不提交整目录压缩包，不复制模型、字体、驱动或共用模块。测试结束应正常退出，让后台完成写入和设备清理。

`testimg/` 的三张图片用于单张识别和 NPU 诊断。单张图片只处理一帧，不能代替摄像头稳定展示、授权到期及四项 CSV 验证。环境排查见 [诊断工具使用说明](诊断工具使用说明.md)，换模型时再阅读 [模型转换参考](../tools/model_conversion/README.md)。
