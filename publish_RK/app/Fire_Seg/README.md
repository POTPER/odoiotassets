# Fire_Seg_V20 学生版与答案版

由V14学生版、V15参考答案版合并为一个目录，共用模型、字体、驱动与运行模块。原V14、V15保留。目录内不包含seg_inference.py，不生成整目录压缩包。

## 入口

| 用途 | 文件 | 说明 |
|---|---|---|
| 学生版 | fire_yolo26_v20.py | 来自V14，保留蓝色初始值及待完善联动示例 |
| 答案版 | fire_yolo26_v20_answer.py | 来自V15，区域配色、项目资料和报警判断为正确参考 |

学生版运行：

```bash
python3 fire_yolo26_v20.py
```

答案版运行：

```bash
python3 fire_yolo26_v20_answer.py
```

一次运行一个入口，两者共用同一摄像头和蜂鸣器。默认摄像头41、NPU auto、蜂鸣器模块2。编号不同时修改各入口的系统设置，或使用 --source /dev/videoN。

两个入口都保留完整的教学说明、配置和识别流程，底层运行模块只有一套。学生修改学生入口，教师使用答案入口对照；无需修改共用模块。

## 两版区别

学生版TODO 1保留原来蓝色，需按题目设置三个区域的范围框及底部名称背景。TODO 2保留可运行示例：材料区火焰数量大于1时请求提示音1，否则静音。示例不是完整答案，已有条件与声音接口都需核对并补全。

答案版的正确设置：

| 项目 | 值 |
|---|---|
| 项目名称 | 分区动火预警调试 |
| 监测点位 | 施工现场监控点01 |
| 钢筋区颜色 | 纯绿色，BGR (0, 255, 0) |
| 临时作业区颜色 | 纯黄色，BGR (0, 255, 255) |
| 材料区颜色 | 纯红色，BGR (0, 0, 255) |

考试编号请填写本人实际考号。范围框与名称背景同色，文字自动选择深浅；火焰检测框仍按置信度显示红色和黄色。

实际授权固定为钢筋区，PERMIT_DURATION默认60秒，可以为完成演示调整为有限正数，保存并重启生效。首帧推理成功后开始计时，无火也计时，到期不自动续期。区域颜色不表示授权始终有效。

答案版的响应：材料区有火请求警报音；钢筋区授权期间有火静音，到期后有火请求提示音1；临时作业区有火请求提示音2；不需报警时提交静音请求。每次只提交一个声音请求。

## CSV与提交

两个入口使用完全相同的四行九列CSV规则。列为：考试编号、项目名称、监测点位、施工区域、区域颜色（BGR）、是否识别到火焰、授权状态、是否警报、警报类型。

四行分别记录材料区、钢筋区授权有效、钢筋区授权到期、临时作业区。钢筋区两个时段独立保存，不相互覆盖。颜色从本次实际绘制配置读取，声音来自本次入口实际提交的请求，不自动填写正确答案、不自动评分，也不输出火焰数量。

每次只在一个区域展示火焰卡片，稳定达到默认0.3秒后记录。无高分火焰、仅低分、多区同时出现或识别异常不能代替单区测试，未完成项目保留“未验证”。同一项重复测试保存最近一次稳定观察。

每次运行按当前用户桌面保存到“成果输出/考试编号/项目名称”，文件名带时间，避免不同运行相互覆盖。正常只保存CSV与本次实际运行入口的源码副本；出现异常时附加异常CSV。不创建源码文件夹，不复制共用模块、模型、字体或驱动。源码副本保留了本次运行的是学生版还是答案版。

“是否警报”表示程序请求，不代表确认实际发声，需现场核对。单张图片的JPEG/JSON输出分别进入output_v20、output_v20_answer，不互相覆盖；实时任务应通过摄像头完成。

## 共用文件

- zone_teaching_support.py：三区显示、倒计时、CSV与声音请求。
- teaching_support.py：成果保存、蜂鸣器后台控制及资源清理。
- detector.py：模型加载和RK3588 NPU结果解析。
- fire_tracker.py、box_smoother.py：目标关联、低分续跟与稳框。
- video_pipeline.py：摄像头、分辨率回退及最新帧流水线。
- io_helpers.py：JPEG和“有/无”UDP通信。
- model/fire_yolo26.rknn、同名JSON：现有模型及类别/输入输出说明。
- Arial-Unicode.ttf：中文字体。
- libSmartSensorDriver.so：蜂鸣器原有驱动。
- requirements.txt：普通依赖说明。

保留RKNNLite和RK3588 NPU推理、fire/smoke两类模型标签中的火焰筛选、高分0.5、已有目标低分续跟0.25、漏检立即无框，以及8088 JPEG、8089“有/无”原协议。不启用云台，不需要Ultralytics或重新训练。

## 环境检查

```bash
python3 fire_yolo26_v20.py --check
python3 fire_yolo26_v20_answer.py --check
```

已有RKNNLite环境可以直接沿用。缺少普通依赖时使用requirements.txt；RKNNLite ARM64 wheel须与板端Python、Runtime和驱动匹配。环境检查不启动NPU或蜂鸣器。

本地针对性验证使用模拟摄像头/NPU/驱动；真实RK3588推理、摄像头表现与发声仍需板端确认。
